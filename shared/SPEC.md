# Спецификация DSL для описания теста

Этот документ — «устав» проекта: он описывает, какой текст принимает ядро, какую модель
отдаёт на выход и что считается ошибкой. Ядро и интерфейс работают только по этим правилам.

## 1. Общие правила

- Файл — обычный текст в кодировке **UTF-8**.
- Перевод строки — `\n` или `\r\n` (парсер нормализует сам).
- Парсер читает файл построчно; **пустые строки игнорируются**.
- Пробелы в начале и конце строки не значимы.
- Директивы `Title`, `H1`, `Style` и коды типов `r`, `c`, `t` пишутся строго в этом регистре.
- Метаданные идут до первого вопроса; порядок директив произвольный.

## 2. Метаданные

| Директива | Назначение | По умолчанию |
|-----------|------------|--------------|
| `Title <текст>` | текст вкладки браузера (`<title>`) | пустая строка |
| `H1 <текст>` | заголовок теста на странице | пустая строка |
| `Style <имя>` | имя CSS-темы оформления | `default` |

Директива без значения (`Title` в конце файла) — ошибка `EMPTY_DIRECTIVE_VALUE`.

## 3. Вопрос

```
? <текст вопроса> <тип>
```

- строка начинается с `?`;
- **тип** — последний токен строки: `r`, `c` или `t`;
- всё, что между `?` и типом, — текст вопроса.

Тип ответа:

| Код | Тип | Что рисуем |
|-----|-----|------------|
| `r` | один правильный вариант | радиокнопки |
| `c` | несколько правильных вариантов | чекбоксы |
| `t` | текстовый ответ | поле ввода |

## 4. Варианты ответа для `r` и `c`

Блок вариантов идёт сразу за строкой вопроса и закрывается маркером `e`.

```
? 2+2= r
- 4 +
- 5
- 6 e
```

- `- <текст>` — вариант ответа;
- `+` в конце строки варианта помечает его правильным. Знак может стоять отдельно
  (`- 4 +`) или приклеиться к тексту (`- C +e`);
- `e` закрывает блок и может стоять отдельно (`- 6 e`) или приклеиться к последнему
  варианту (`- C +e`).

Требования:

- для `r` правильный вариант должен быть **ровно один**;
- для `c` правильных вариантов должно быть **один и более**.

## 5. Текстовый ответ для `t`

```
? Text question t
_ My answer
```

- `_ <ответ>` задаёт эталонный ответ;
- сравнение с ответом пользователя: обрезка пробелов по краям, **без учёта регистра**;
- строка `_` без текста — ошибка `MISSING_TEXT_ANSWER`.

## 6. Ошибки

Ошибка всегда содержит **номер строки**, **код** и понятное сообщение:

```
Строка 7: у вопроса нет правильного варианта (NO_CORRECT_OPTION)
```

| Код | Когда возникает |
|-----|-----------------|
| `UNKNOWN_DIRECTIVE` | строка не распознана парсером |
| `EMPTY_DIRECTIVE_VALUE` | у директивы нет значения |
| `EMPTY_QUESTION` | после `?` нет текста вопроса |
| `EXPECTED_ANSWER_TYPE` | после вопроса нет типа `r`/`c`/`t` |
| `OPTION_OUTSIDE_OPTIONS` | строка `-` вне блока вариантов |
| `EMPTY_OPTION` | вариант `-` без текста |
| `ANSWER_OUTSIDE_QUESTION` | строка `_` вне вопроса типа `t` |
| `NO_OPTIONS` | блок закрыт, но вариантов не было |
| `NO_CORRECT_OPTION` | у вопроса `r`/`c` нет ни одного `+` |
| `TOO_MANY_CORRECT_OPTIONS` | у вопроса `r` больше одного `+` |
| `MISSING_TEXT_ANSWER` | у вопроса `t` нет строки `_` |
| `BLOCK_NOT_CLOSED` | блок вариантов не закрыт маркером `e` |

Парсер не бросает исключений на некорректном тексте: он возвращает модель (возможно,
частичную) и список ошибок.

## 7. Модель и совместимость с `question-bank.js`

Модель повторяет формат вопросов, который уже использует `question-bank.js`
(`{ text, type, options: [{ text, correct }], answer }`), чтобы ядро и интерфейс
не расходились.

| Модель | JSON | Комментарий |
|--------|------|-------------|
| `Quiz.title` | `title` | из `Title` |
| `Quiz.heading` | `heading` | из `H1` |
| `Quiz.style` | `style` | из `Style`, по умолчанию `default` |
| `Quiz.questions` | `questions` | список вопросов |
| `Question.text` | `questions[].text` | текст вопроса |
| `Question.type` | `questions[].type` | `r` / `c` / `t` |
| `Question.options` | `questions[].options` | только для `r` и `c` |
| `Option.text` | `options[].text` | текст варианта |
| `Option.correct` | `options[].correct` | признак правильного |
| `Question.answer` | `questions[].answer` | только для `t` |

## 8. Пример из задания

```
Title My title
H1 Super Test

? 2+2= r
- 4 +
- 5
- 6 e

? Second question c
- A
- B +
- C +e

? Text question t
_ My answer
```

Результат разбора:

```json
{
  "title": "My title",
  "heading": "Super Test",
  "style": "default",
  "questions": [
    {
      "text": "2+2=",
      "type": "r",
      "options": [
        { "text": "4", "correct": true },
        { "text": "5", "correct": false },
        { "text": "6", "correct": false }
      ]
    },
    {
      "text": "Second question",
      "type": "c",
      "options": [
        { "text": "A", "correct": false },
        { "text": "B", "correct": true },
        { "text": "C", "correct": true }
      ]
    },
    {
      "text": "Text question",
      "type": "t",
      "answer": "My answer"
    }
  ]
}
```

Готовые файлы примера — в `shared/examples/`.

## 9. Что сознательно не поддерживается

- вложенные вопросы и блоки;
- несколько текстовых ответов на один вопрос;
- подсветка синтаксиса и редактор DSL — только обычное текстовое поле;
- экранирование `+` и `e` в тексте варианта: вариант не может заканчиваться на `+`
  или `e`, если это не маркер.
